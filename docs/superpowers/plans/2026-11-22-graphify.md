**Goal:** Zainstalować Graphify globalnie (user scope) i skonfigurować repo tak, żeby graf był commitowany, aktualizował się sam przy każdym commicie, a agent Claude Code musiał odpytać graf przed czytaniem plików.

**Architecture:**
- CLI `graphify` (pakiet PyPI `graphifyy`) przez `uv tool`, skill `/graphify` w `~/.claude/skills/` (user scope).
- W repo commitujemy tylko `graphify-out/graph.json`, z merge driverem.
- Aktualizację robi skrypt `.husky/graphify-update.sh` wywoływany z `pre-commit`, więc graf trafia do **tego samego** commita.
- Wymuszanie: hooki PreToolUse w `.claude/settings.json` (projekt), z `GRAPHIFY_HOOK_STRICT=1` i `GRAPHIFY_HOOK_STRICT_TTL=300`.

**Tech Stack:** Graphify 0.9.115 (`graphifyy`), uv 0.13.9, Python 3.13, husky 9, Claude Code hooks, git merge driver.

**Spec:** brak osobnego speca. Źródła (czytane 2026-11-22):
- dokumentacja Graphify: README; `graphify/skills/claude/references/{hooks,update}.md`; `graphify/always_on/claude-md.md` z gałęzi `v8`;
- docs.graphify.com: team-workflows, vibe-coding, supported-inputs, configuration, environment-variables;
- kod `graphify/cli.py` (warunki strict mode).

Decyzja: [ADR-0011](../../adr/0011-graf-wiedzy-graphify.md).

**Jak użyć u siebie:** plan zakłada repo z husky (`core.hooksPath`), Makefile i Claude Code. Bez husky blok z Task 3 wklej do `.git/hooks/pre-commit` albo do `.githooks/` z `core.hooksPath`. Nazwy katalogów `backend/` i `frontend/` w ostrzeżeniu hooka zamień na swoje katalogi z kodem.

## Global Constraints

- **Instalacja globalna:** `uv tool install graphifyy` + `graphify install` (skill w `~/.claude/skills/graphify/`). **Nie** `graphify install --project`. `graphify install` dopisuje też krótką sekcję o skillu do globalnego `~/.claude/CLAUDE.md`.
- **Nazwa pakietu:** `graphifyy` (podwójne „y”). Inne pakiety `graphify*` na PyPI nie są oficjalne.
- **Praca na zwykłej gałęzi** od `main`, bez worktree.
- **Co trafia do repo:** **tylko** `graphify-out/graph.json` (`.gitignore`: `graphify-out/*` + `!graphify-out/graph.json`). Raport, HTML, cache i manifest budują się lokalnie.
- **`.gitattributes`:** `graphify-out/graph.json merge=graphify linguist-generated=true -diff`.
- **Moment aktualizacji: `pre-commit`.**
  - Komenda: `PYTHONHASHSEED=0 graphify update .`. Analizuje tylko kod (AST), bez LLM, z deterministycznym clusteringiem.
  - Nie post-commit: zostawia graf jako niezacommitowaną zmianę.
  - Nie pre-push: wymagałby dodatkowego commita.
  - Nie `pre-merge-commit`: git zapisuje drzewo merge commita przed hookiem.
- **Nie używać `graphify hook install`**: husky ustawia `core.hooksPath=.husky/_`, więc hooki w `.git/hooks` nigdy się nie uruchomią.
- **Hook commita nie może blokować pracy bez graphify** (CI, GUI, inny klon): przy braku `graphify` w PATH albo `GRAPHIFY_SKIP_HOOK=1` hook pomija aktualizację z komunikatem na stderr i kończy się kodem 0. Błąd samego `graphify update` przerywa commit.
- **Wymuszanie dla agenta:** hooki `graphify hook-guard search|read|compact` z `graphify claude install` oraz `env` z `GRAPHIFY_HOOK_STRICT=1` i `GRAPHIFY_HOOK_STRICT_TTL=300` w `.claude/settings.json`.
- **Komendy w `.claude/settings.json`** wywołują samo `graphify`, bez ścieżek absolutnych z `/Users/...` (prywatność i przenośność).
- **Obrazy (`*.png`, `*.svg`) w `.graphifyignore`:** każdy wymaga osobnej ekstrakcji wizyjnej (osobnego subagenta), a zrzuty makiet nie wnoszą wiedzy o kodzie.

1. **Brak `graphify` w PATH przy commicie** (CI, git w GUI VS Code, świeży klon): commit przechodzi z komunikatem „pominięto”. ✅ Test: Task 3, Step 5.

### Task 3: Automatyczna aktualizacja w pre-commit (husky)

**Files:**
- Create: `.husky/graphify-update.sh`
- Modify: `.husky/pre-commit`

**Interfaces:**
- Consumes: `graphify update .`; `graphify-out/graph.json` z Task 2.
- Produces: każdy commit ze zmianami poza grafem zawiera aktualny `graph.json`.

- [x] **Step 1: Skrypt `.husky/graphify-update.sh`**

```sh
# Aktualizacja grafu Graphify (tylko kod, bez LLM) w pre-commit. Nie w pre-merge-commit: git zapisuje drzewo merge commita przed hookiem, więc `git add` z hooka zostałby tylko w indeksie.
# Hooki husky, a nie `graphify hook install`: husky ustawia core.hooksPath, więc hooki z .git/hooks się nie uruchamiają.
# Bez zmian staged poza grafem — nic do zrobienia.
[ -n "$(git diff --cached --name-only -- . ':!graphify-out/graph.json')" ] || exit 0
if [ "${GRAPHIFY_SKIP_HOOK:-0}" = "1" ] || ! command -v graphify >/dev/null 2>&1; then
  echo "graphify: pominięto aktualizację grafu (GRAPHIFY_SKIP_HOOK=1 albo brak graphify w PATH)" >&2
  exit 0
fi
# shortcut: graf budowany z drzewa roboczego, nie z indeksu — przy niezacommitowanych plikach tylko ostrzegamy.
if [ -n "$(git status --porcelain --untracked-files=normal -- backend frontend | grep -v '^[MADRC] ')" ]; then
  echo "graphify: uwaga — niezacommitowane/nieśledzone pliki w backend/ lub frontend/ trafią do grafu" >&2
fi
PYTHONHASHSEED=0 graphify update . || exit 1
git add graphify-out/graph.json
```
`|| exit 1` jest potrzebne, bo husky uruchamia hooki przez `sh -e`. W `sh -e` błąd po lewej stronie `&&` nie przerywa skryptu, więc commit przeszedłby z nieaktualnym grafem.

## Wnioski z wdrożenia

Różnice względem pierwszej wersji planu i rzeczy, których nie ma w dokumentacji Graphify:

1. **Hook commita działa od razu po zapisaniu pliku.** Hook był w pliku roboczym, gdy commitowałem inny plik. `graph.json` trafił wtedy do niewłaściwego commita i trzeba było przebudować dwa lokalne commity.
2. **`pre-merge-commit` nie zapisuje grafu w merge commicie.** Git tworzy drzewo przed hookiem. Graf w merge commicie to unia z merge drivera, a węzły usunięte na jednej gałęzi mogą wrócić do następnego commita.
3. **Przycisk merge i „Update branch” na GitHubie nie używają drivera.** Jednoliniowy, prawie zawsze zmieniony `graph.json` daje tam konflikt całego pliku, więc mergujemy lokalnie.
4. **`rm graph.json && graphify update .` buduje graf tylko z kodu.** Znikają węzły z dokumentów i hyperedges, u nas z 997 węzłów i 15 hyperedges do 1042 węzłów i 0 hyperedges. Dlatego `git checkout --theirs`.
5. **Graf powstaje z drzewa roboczego, nie z indeksu.** Nazwa nieśledzonego pliku i jego identyfikatory trafiły do commitowanego grafu (przegląd zrobił to testem). Wartości nie trafiły, tylko nazwy.
6. **`graphify update` ponownie liczy społeczności.** Część nazw nadanych przy pełnym buildzie zastępują nazwy węzła centralnego. Odświeża je `graphify label` albo `/graphify --update`.
7. **Strict nie jest per sesja.** Znacznik zapytania jest wspólny dla projektu. Przy domyślnym TTL (30 min) pierwszy test nie dał blokady, bo kilka minut wcześniej uruchomiłem `graphify explain`.
8. **Commit tylko z Markdownem też przebudowuje graf** (AST), ale treść dokumentów zostaje stara. `graphify section` może wtedy zwracać nieaktualny tekst.
9. **Subagenci zapisywali paczki skryptem Pythona zamiast narzędziem Write.** Wynik był poprawny, a pokrycie (przeczytane linie) zgadzało się z `wc -l` dla wszystkich 34 plików.
