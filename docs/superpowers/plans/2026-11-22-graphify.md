# Graphify — graf wiedzy repo (instalacja globalna + konfiguracja teamable) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zainstalować Graphify globalnie (user scope) i skonfigurować teamable tak, by graf był commitowany do repo, aktualizował się sam przy każdym commicie, a agent Claude Code musiał odpytać graf przed czytaniem plików.

**Architecture:** CLI `graphify` (pakiet PyPI `graphifyy`) przez `uv tool` + skill `/graphify` w `~/.claude/skills/` (user scope). W repo: commitowany jest tylko `graphify-out/graph.json` (z merge driverem), aktualizacja AST w istniejącym hooku `.husky/pre-commit` (graf trafia do **tego samego** commita), wymuszanie przez hooki PreToolUse w `.claude/settings.json` (projekt) z `GRAPHIFY_HOOK_STRICT=1`.

**Tech Stack:** Graphify (`graphifyy`), uv, Python 3.13 (pyenv), husky 9, Claude Code hooks, git merge driver.

**Spec:** brak osobnego speca — źródłem są dokumentacja Graphify (README, `graphify/skills/claude/references/{hooks,update}.md`, `graphify/always_on/claude-md.md` z gałęzi `v8`; docs.graphify.com: team-workflows, vibe-coding, supported-inputs, configuration, environment-variables — czytane 2026-11-22) i ustalenia z rozmowy. Decyzja trafia do ADR-0011 (Task 5).

## Global Constraints

- Instalacja narzędzia **globalna**: `uv tool install graphifyy` + `graphify install` (skill w `~/.claude/skills/graphify/`). **Nie** `graphify install --project` (nie kopiujemy skilla do repo).
- Pakiet to `graphifyy` (podwójne „y”); inne `graphify*` na PyPI nie są oficjalne.
- Pracujemy na zwykłej gałęzi `chore/graphify` od `main` — **bez worktree**.
- W repo commitujemy **tylko** `graphify-out/graph.json` (`.gitignore`: `graphify-out/*` + `!graphify-out/graph.json`). Report/HTML/cache budują się lokalnie.
- `.gitattributes`: `graphify-out/graph.json merge=graphify linguist-generated=true -diff`.
- Aktualizacja w **pre-commit** (nie post-commit — ten zostawia graf jako niezacommitowaną zmianę; nie pre-push — wymagałby dodatkowego commita). Komenda: `PYTHONHASHSEED=0 graphify update .` (AST-only, bez LLM, deterministyczny clustering).
- **Nie używać** `graphify hook install`: husky ustawia `core.hooksPath=.husky/_`, więc hooki w `.git/hooks` nigdy się nie uruchomią.
- Hook commita nie może blokować pracy bez graphify (CI, GUI, inny klon): brak `graphify` w PATH lub `GRAPHIFY_SKIP_HOOK=1` → pominięcie, exit 0.
- Wymuszanie: hooki `graphify hook-guard search|read` z `graphify claude install` + `"env": {"GRAPHIFY_HOOK_STRICT": "1"}` w `.claude/settings.json`. Strict blokuje **pierwszy** odczyt pliku w sesji, dopóki agent nie wykona `graphify query|path|explain` (ważne 1800 s, `GRAPHIFY_HOOK_STRICT_TTL`); potem tylko podpowiada. Grep po katalogach i Bash nie są blokowane — to limit narzędzia, nie do obejścia konfiguracją.
- Komendy w commitowanym `.claude/settings.json` bez ścieżek absolutnych z `/Users/...` (prywatność + przenośność) — samo `graphify`.
- Dokumentację piszemy po polsku (CLAUDE.md projektu); sekcja `## graphify` generowana przez narzędzie zostaje po angielsku.

## Review Focus

1. **Brak `graphify` w PATH przy commicie** (CI, VS Code git GUI, świeży klon) → commit przechodzi, graf nie jest ruszany. Test: Task 3, Step 5.
2. **Hook Claude Code „fail open”** — przy złej ścieżce/PATH guard milczy i nic nie wymusza; wygląda na działające, a nie działa. Test: Task 4, Step 6 (realna sesja musi dostać deny).
3. **Konflikt merge na `graph.json`** po równoległych gałęziach → merge driver robi unię; przy błędzie odtworzenie `rm graphify-out/graph.json && graphify update . && git add graphify-out/graph.json`. Test: Task 2, Step 7 (`git check-attr` + `git config merge.graphify.driver`).
4. **Zmiany w Markdown (specy, ADR) nie trafiają do grafu** — pre-commit aktualizuje tylko kod (AST); dokumenty wymagają `/graphify --update` w Claude Code (przechodzi przez model). Udokumentowane w README (Task 5).
5. **Wrażliwe dane w commitowanym grafie** — graf zawiera nazwy i ścieżki z kodu; `.env` jest filtrowany wbudowanie, ale sprawdzamy przed pierwszym commitem. Test: Task 2, Step 5.

- [ ] **Step 2: Reguły ignorowania**

`.gitignore` — dopisz:
```

graphify-out/*

```
`.graphifyignore` (scan root) — `.claude/` (lokalne ustawienia i pamięć agenta nie są wiedzą o projekcie). `node_modules`, `dist`, lockfile i `.env` są pomijane wbudowanie.

`.prettierignore` (nowy, root) — `graphify-out/`. Powód: `.vscode/settings.json` ma `editor.formatOnSave` z Prettierem, a ręczne `npx prettier --write .` z roota przeformatowałoby jednoliniowy `graph.json` (wielki diff, zepsuty determinizm). Pozostałe narzędzia nie wymagają zmian: lint-staged łapie tylko `frontend/**` i `backend/**`, ESLint/oxlint/`prettier --check src` w CI działają w `frontend/` i `backend/`, obrazy Docker budują się z kontekstów `./backend` i `./frontend`.

- [ ] **Step 3: `.gitattributes` i merge driver**

`.gitattributes`: `graphify-out/graph.json merge=graphify linguist-generated=true -diff`

`Makefile` — cel `graphify-setup` (dopisz do `.PHONY`), rejestruje driver w bieżącym klonie wg docs team-workflows:
```make
graphify-setup: ## Rejestruje merge driver grafu Graphify w tym klonie (raz na klon)
	@PY="$$(sed -n '1s/^#!//p' "$$(command -v graphify)")"; \
	git config merge.graphify.name "graphify graph.json union merge"; \
	git config merge.graphify.driver "\"$$PY\" -m graphify merge-driver %O %A %B"
```
(Dopasuj format komentarza/`help` do istniejących celów Makefile.)

Run: `make graphify-setup`

### Task 3: Automatyczna aktualizacja w pre-commit (husky)

**Files:**
- Modify: `.husky/pre-commit`

**Interfaces:**
- Consumes: `graphify update .`; `graphify-out/graph.json` z Task 2.
- Produces: każdy commit ze zmianami poza grafem zawiera aktualny `graph.json`.

- [ ] **Step 1: Dopisz blok po `npx lint-staged`**

Zachowanie (wg docs team-workflows, dopasowane do husky):
- `GRAPHIFY_SKIP_HOOK=1` → pomiń;
- `command -v graphify` nie znajduje → pomiń, exit 0 (bez komunikatu-błędu);
- brak staged zmian poza `graphify-out/graph.json` (`git diff --cached --name-only -- . ':!graphify-out/graph.json'` puste) → pomiń;
- inaczej: `PYTHONHASHSEED=0 graphify update .` i `git add graphify-out/graph.json`; błąd `graphify update` przerywa commit (nie commitujemy niespójnego grafu).

Komentarz w pliku jedną linią: dlaczego pre-commit, a nie `graphify hook install` (husky `core.hooksPath`).

- [ ] **Step 2: Commit hooka**

```bash
git add .husky/pre-commit
git commit -m "chore(graphify): update graph in pre-commit hook"
```

Expected: commit przechodzi (hook się uruchamia — w commicie jest tylko `.husky/pre-commit`, więc `graph.json` może się nie zmienić).
