# Etap 4.5 — Uwierzytelnianie (Better Auth) — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Logowanie e-mail + hasło (Better Auth, zamknięta rejestracja) i prywatny profil per użytkownik w Teamable.

**Architecture:** Better Auth montowany w Express 5 pod `/api/auth/*splat` z adapterem MongoDB na połączeniu Mongoose; `requireAuth` wyznacza `req.currentUser`, a istniejące endpointy `/api/profile` działają na profilu `_id = userId`. Frontend Vue pyta o sesję przez `better-auth/vue` i pokazuje ekran logowania albo dotychczasowy widok profilu. Jeden origin (proxy Vite / nginx), bez CORS, CSRF przez `originCheck`.

**Tech Stack:** Express 5, Mongoose 9, Better Auth (pinned), Zod 4, Vue 3, Vitest + Testcontainers, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-22-etap4-5-auth-design.md` (+ ADR-0001…0005 w `docs/adr/`)

## Global Constraints

- Implementacja startuje **po przejrzeniu wyników review z issue #5**; jeśli paczka „Auth-prep" coś zmieni — najpierw poprawka specu i planu.
- `better-auth` **pinned** (dokładna wersja, bez `^`), ta sama w `backend` i `frontend`.
- `emailAndPassword: { enabled: true, disableSignUp: true, minPasswordLength: 8, maxPasswordLength: 128 }`; **bez** `session.cookieCache`; domyślne `expiresIn`/`updateAge` i rate limit.
- Adapter: `mongodbAdapter(mongoose.connection.db)` z `better-auth/adapters/mongodb`, **bez `client`** (bez transakcji — standalone `mongo:7`).
- `advanced.ipAddress.ipAddressHeaders: ['x-real-ip']`.
- Mount Express 5: `app.all('/api/auth/*splat', …)` **przed** `express.json()`.
- `BETTER_AUTH_SECRET`: wymagany, min. 32 znaki, **bez wartości domyślnej**, nigdy w repo (także dev). `BETTER_AUTH_URL`: wymagany URL = publiczny origin aplikacji (origin frontendu).
- `cors` i `@types/cors` usunięte; `VITE_API_BASE_URL` usunięty; klient bez `baseURL`.
- Kontrakt HTTP `Profile` bez zmian (5 pól, bez `_id`). `avatarUrl` = `/api/profile/avatar?v=<ts>`.
- Komunikat błędu logowania (UI): **„Niepoprawny e-mail lub hasło"**.
- Testy i komunikaty po polsku, jak w istniejącym kodzie; każde FR-14…FR-19 ma test, opisany ID w nazwie testu.

## Review Focus

1. **E-mail logowania z inną wielkością liter** (`Owner@Example.com` vs utworzony `owner@example.com`) → logowanie działa. Test w Task 2.
2. **Upload avatara bez sesji** → 401 i **żaden plik nie trafia na dysk** (multer nie może ruszyć przed `requireAuth`). Test w Task 4.
3. **Zmiana użytkownika w tej samej karcie** (wyloguj A → zaloguj B) → dane A nie pojawiają się nawet na chwilę w widoku B. Test w Task 6.
4. **`user:create` z istniejącym e-mailem** → czytelny błąd, brak drugiego konta i brak osieroconego `account`. Test w Task 2.
5. **`DELETE /api/profile` przez A** → katalog avatara B nietknięty. Test w Task 4.
